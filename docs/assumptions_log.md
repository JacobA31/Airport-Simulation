# Assumptions Log (Report §3)

D-numbers refer to entries in `DECISIONS.md`.

## Assumptions in place

| Assumption | Source |
|---|---|
| Demand is identical across flight times | Handout |
| FIFO queue discipline in every queue (business and coach queues at check-in and security) | Team |
| Travel time from security to the gate is negligible; walking time from check-in to security is also zero | Handout, D19 |
| Every passenger travels alone | Handout |
| Horizon is 7 days (10,080 min), starting empty, with no warm-up period | Handout §6.1, D12 |
| Check-in service components are independent; the total is their sum | Team |
| Bag processing: one independent Exp(mean 1 min) per checked bag | Team (A6) |
| "Other problems/delays" (Exp, mean 3 min) applies to every passenger, since the handout gives no probability | D4 |
| Checked bags are generated independently per passenger, by passenger type | Handout |
| Provincial passengers per cabin per flight ~ Binomial(seats, occupancy probability); every booked passenger shows up | D10, D22 |
| Bookings and lead times for all provincial flights are generated at t = 0 | D18 |
| Provincial lead time is truncated normal (mean 75, variance 50) with limits [0, 180] min, generated by inverse transform | D11 |
| First provincial departure is 06:00 on day 1; the t = 0 departure is excluded, since an empty system at t = 0 has no one who arrived beforehand (28 provincial and 168 commuter flights per horizon) | D12 |
| Check-in staffing: every counter is staffed for the whole horizon at $35/hour; security staff are not costed | D12 |
| Commuters go through check-in (zero-bag commuters do not skip it) and then security | D5 |
| Passengers still in the system at departure continue through processing (`missed_pax_policy: continue`) | D6, D21 |
| A provincial miss is recorded at the departure instant, for every booked passenger not yet at the gate | D16 |
| Business and coach resources are not shared in the baseline (`cross_use: none`) | D7, D20 |
| Commuter gate queue: FIFO by gate-arrival (security completion) time | D8 |
| Simultaneous events are processed in this order: security completion, check-in completion, passenger arrival, flight departure, end of simulation; ties within one type follow scheduling order | D9 |
| Revenue: provincial fares for all booked passengers at departure, refunds as a separate line, commuter fare at boarding (commuters still waiting at the end of the horizon earn nothing); net revenue = gross − refunds | D13 |
| Refund: fare of a missed provincial passenger whose lead time was at least 90 min | D13 |
| Operating cost: every scheduled flight in the horizon, even if empty ($12,000 provincial, $1,500 commuter) | D13 |
| The 5% constraint is check-in staffing cost ÷ net ticket revenue over the horizon | D13 |
| Waiting-time means include only passengers whose service started before the end of the horizon; those still waiting are reported through `pax_in_system_end` and queue lengths | D17 |
| One independent random-number stream per source of randomness, all seeded from `simulation.base_seed` | Team |

## Baseline characteristics to state in the report

| Characteristic | Notes |
|---|---|
| Baseline is overloaded | With "other delays" applied to every passenger (D4), coach check-in offered load is about 1.8× capacity, and early smoke runs showed about 90% of provincial passengers missing. These came from placeholder variates, so confirm with the pilot (`pax_in_system_end`, `end_checkin_waiting`, `end_security_waiting`). D4 is a config flag and a candidate question for the TA |
| Waits depend on the horizon | Baseline queues grow all week, so mean waits and queue lengths depend on the 7-day horizon. The confidence intervals remain valid because the horizon is fixed; say this when interpreting them |
| Finance reacts weakly to missed flights | Booked provincial seats earn revenue whether or not the passenger flies, and only passengers who arrived at least 90 min early are refunded (about 1.5%), so profit barely changes and the 5% staffing limit is slack. State this explicitly in the trade-off discussion (§12) |
| Commuter gate is critically loaded | 40 commuters/hour meet 40 seats/hour, so once upstream capacity is added, gate waits and left-behind counts grow. Relevant to the choice of decision area |
